## 5. HUMAN決裁

### 5-1. 実況エンジンの方針（2026-07-26）

- **LLM版を推奨構成とする**（実況・解説ともにLLMで生成）
- **LLM失敗時はルール版へフォールバックする**（現行実装のまま、変更不要）
- **ルール版のみに固定できる設定を利用可能にする**（現行UIに存在するが表現が不明瞭）
- **コードの既定プロバイダ `LLM_PROVIDER=disabled` は変更しない**（利用者ごとにプロファイル設定で選ぶ方式を維持）

根拠は #331 の実データ。ルール版には次の実害がある。

- 生の英語出力を音声に混ぜる（`今見えている出力は「Would you like to run the following command?」です`）
- 内部状態 `未判定段階` が音声に漏れる
- 同一文を反復する（F2でエラー3件が同一文）

いずれも「非エンジニア・非英語話者が日本語で監督する」という #300 の目的に対する実害である。一方、ルール版はレイテンシ0・確実性・簡潔さで優れており、フォールバック先としての価値は変わらない。

### 5-2. 評価の厳密化は打ち切り（Gino提言、HUMAN了承）

> 壊れると作業を止める、秘密を漏らす、重要な呼びかけを逃す部分は厳しく自動テストする。
> 実況の分かりやすさや自然さは、少数の実セッションで人間が確認する。

Phase B の盲検評価は「一度判断するための簡易実験」に格下げした。中止したもの：フェーズ語の後処理除去 / fixture・設問のさらなる追加 / 評価ハーネスの高度化 / 正答率80%・100%の製品ゲート化。

## 7. 引き継ぎメモ

- **評価スクリプトは `.env` を読まない**。`dotenv/config` はサーバー本体のみ。鍵はリポジトリ外に置き、`set -a; source ...; set +a` か `tsx --env-file=` で渡す
- **共有チェックアウトの `apps/server/dist` に古いテスト成果物が残っていると、`pnpm -C apps/server test` がコンパイル済みテストを二重実行し、本数が水増しされる**（47ファイル558本と表示されるが実数は41ファイル）。再検証時は worktree を使うか `--exclude '**/dist/**'` を付ける
- Gemini の API キーは本日の測定後に削除する運用。再測定時に再発行する
- 秘密情報を含むファイルの編集をエージェントに任せると、差分表示で値が露出する。置換コマンドで実行させるか HUMAN が直接編集する
