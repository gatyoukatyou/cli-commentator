## 4. 重要な発見・リスク

### ルールセットが前提とする形式は、実際には存在しない

`apps/server/src/rulesets/claude.ts` は `⏺ Read(...)` `⏺ Bash(...)` 形式を7ルールで拾う設計。しかし実際の Claude Code v2.1.220 の出力を計測すると：

| パターン | 実出力での出現数 |
|---|---|
| `⏺ Xxx(` 形式 | **0** |
| `Read(` / `Bash(` / `Grep(` 等 | **0** |
| `⏺` 単体 | 8 |
| `⎿` | 1 |

**構造化ルール7本は現行のClaude Codeに対して一度も発火しない。**

原因はテストフィクスチャが手書きの合成データだったこと：

```
apps/server/test/fixtures/claude.basic.log
⏺ Read(/Users/demo/project/README.md)
⏺ Glob(src/**/*.ts)
⏺ Bash(pnpm test)
```

1行1ツールの理想形で、実TUI出力はこの形にならない。**実データで検証されたことがない。**

系として、`detect.ts` の auto 判定も同じパターンを見ているため、`LOG_SOURCE=auto` では実セッションが claude と判定されることもない（アプリで `ログ判定: claude` と出ていたのは起動プリセットの明示指定によるもの）。

### 実出力に実在する手がかりは3つ

```
⎿  $ ls -1 /Users/demo/project/docs        ← 実行コマンドそのもの（最も価値が高い）
⏺docs/の中身は以下の通りです。               ← AIの回答本文
Listed 3 directories, ran 1 shell command  ← 作業要約
```

`⎿ $ <コマンド>` は既存の `command-analysis.ts`（`isTestExecution` / `isSearchExecution` / `extractSearchPattern` / `representativeGlossaryTerm`）にそのまま流せる。これがC'案の核。

### 部分再描画による本文破壊はフィルタでは直せない

```
rqurements.nmd / requirement.ja.m
certificsecretsen.md / certificate-secrets.ja.md
ies, runing1 shell command…
```

信頼できる行だけを採用する方式が必要な理由がこれ。

### 計測用スニペット（手順1・5で使う）

```ts
// apps/server/src/tests/ に一時ファイルとして置き、PR前に必ず削除する
import fs from "node:fs";
import { extractEvents } from "../extract.js";
import { createEscapeCarry } from "../terminal-escapes.js";

const fixture = JSON.parse(
  fs.readFileSync("apps/server/test/fixtures/claude-tui/real-session-2.1.220.json", "utf8")
);
const carry = createEscapeCarry();
for (let i = 0; i < fixture.raw.length; i += 512) {
  for (const ev of extractEvents(carry(fixture.raw.slice(i, i + 512)), "claude")) {
    console.log(ev.type, JSON.stringify(ev.detail?.slice(0, 100)));
  }
}
```

読み上げまで見る場合は `commentByRules` と `applySpeechContract` を通す。
セッション文脈の progress 間引きは実時間ベースなので、
`createSessionContext({ now: () => t })` で時刻を制御しないと結果が変わる。

### 注意

- フィクスチャの `raw` はエスケープシーケンスを含む生のPTYペイロード。
  チャンク境界での分断を再現することが目的なので、整形して保存し直さないこと
- 機微情報はサニタイズ済み（ホームパス・アカウント状態・利用枠）。
  新しく実データを追加する場合も同じ処理を通すこと
