# 二人の実況・解説と共通操作の評価

本資料は評価手順です。実施結果や達成済みの性能を示すものではありません。

## HUMANが確かめること

架空の作業デモを使用します。字幕を読んで操作方法を確かめた後、画面を見ずに音声とキーボードで同じ流れを試します。実際の開発作業や共有は行いません。

1. デモであることと、実際のファイルを変更しないことがわかります。
2. 作業を始めると、実況役と解説役の発言を区別できます。声が同じ場合も役割名で区別できます。
3. 各段階で「今何をしている」「何が変わった」「自分の返答が必要か」を説明できます。
4. テスト失敗から再修正へ進んでも、作業全体が終了したと誤解しません。
5. 承認待ちになると、何を承認するのかと選択肢がわかります。「次へ」だけでは承認を通過しません。
6. 保留・詳しい説明・承認・拒否をキーボードで選べます。
7. 説明の読み上げを止めても作業状態は変わりません。作業を停止した場合は、それ以後進めません。
8. 再開始すると、前の承認が新しい作業に適用されません。

スクリーンリーダーでは、状態変更を知るために手動で画面を探し回る必要がないか、実況音声と読み上げが重ならないかも確かめます。見えている開発者だけの確認を、視覚障害のある利用者による検証の代わりにはしません。

## AIによる自動確認

- 同一プロセスのMCPツール操作の結果をHTTP側で取得でき、逆方向も同じ状態に収束します。
- 開始・進行・停止の不正な入力を拒否します。
- 承認対象の取り違え、再送、別セッションへの適用を防ぎます。
- AI側の入口から人として承認することはできません。
- 根拠と説明が対応し、返したスナップショットを外部で変更しても内部状態が変わりません。
- 停止後や承認待ちで無条件に進行しません。
- MCPの標準クライアントで接続し、初期化・ツール一覧・操作・正常終了を確認します。
- 外部ページからの意図しない操作、過大な入力、HTMLの差し込みを防ぐ境界を確認します。

## 記録の仕方

各場面の質問と利用者の理解を短く記録します。操作できなかった箇所、説明の食い違い、聞き返し回数、声の区別、疲労感も残します。利用者の個人情報や生の音声は、許可なく保存・共有しません。

「自然に聞こえた」と「内容を正しく理解できた」を別に評価します。架空デモでの成功と、実際のCLI接続の成功も別に記録します。

## 後続段階で測る性能

以下は初期目標です。現在の達成値ではありません。

- 説明停止から無音まで95パーセンタイル500ms以内。
- 確定した重要状態から短い通知の開始まで95パーセンタイル1秒以内。
- 古くなった通常発話を再生し続けないこと。
- 評価シナリオ内で誤った終了通知・承認の混同・無断実行が0件であること。
- 日本語品質、音声開始遅延、ピークメモリ、作業AIとの同時実行、通信断時の動作。

音声停止と実作業停止の時間は別に測ります。評価シナリオで問題がなかったことを、あらゆる場面で問題が起きない保証として扱いません。

## 段階2：実接続を試すときの追加確認

段階2の起動方法と対応範囲は [Codex接続](codex-bridge.ja.md) を参照してください。架空モードの確認と実接続の確認を混同しません。

| 操作 | 確かめること |
|---|---|
| 実接続の画面を開く | 実際のCodexを使うこと、練習用ファイルが対象であること、サブスクの利用枠を使うことを理解できますか |
| 練習タスクを開始する | 今何を調べているか、まだ結果を確認していない場面が分かりますか |
| 説明と根拠を読む・聞く | AIの報告と、実行したコマンドの終了結果を区別できますか |
| 返答が終わる | 返答完了と、Codexプロセスの終了が別だと分かりますか |
| 作業を停止する | 停止依頼中と停止確認後の違いが分かりますか。音声だけを止める操作と取り違えませんか |
| もう一度開始する | 古い説明や承認が新しい作業のものとして残りませんか |
| 接続が失われる | 状態を確認できないことと、次に取れる操作が分かりますか |

承認要求が来たときは、何を実行するか、どこに作用するか、許可するとアクセス範囲がどう変わるかを確認します。表示した一件以外も許すような表現がないか確かめます。通常の練習タスクでは承認要求が出ないこともあります。その場合は「実接続で承認を試した」と記録しません。模擬接続での承認テストは別の結果として記録します。

## 2026-10-31の追加確認（画面を見ない操作と音声ガイド）

単一キー操作・自動読み上げ・説明の音声再生は、いずれも初期状態ではオフです。オンにする場合は、次の点を確かめてください。

| 操作 | 確かめること |
|---|---|
| 単一キー操作をオンにする | `j`（もう一度読む）、`k`（詳しく説明）、`h`（使える操作の案内）、`Escape`（音声を止める）が動きますか。入力欄や変換中、修飾キー付きでは誤作動しませんか |
| 開始・承認・拒否・作業停止 | 単一キーでは実行されず、ボタン操作が必要だと分かりますか |
| 自動読み上げをオンにする | 開始・承認待ち・回答完了・作業停止・接続終了・失敗・状態不明だけが短く読まれますか。画面が変わらない間は繰り返しませんか |
| 作業停止と接続終了 | 作業の停止とCodex接続の終了を別の出来事として理解できますか |
| 説明の音声再生をオフにする | 「詳しく説明」の文は画面に残り、音声だけが止まりますか。オフにした後に遅れて届いた説明が勝手に読まれませんか |
| 音声を止める | 音声だけが止まり、AIの作業やCodexとの接続は続いていると分かりますか |

2026-10-31の自動検証は、型検査、ブラウザ用JavaScriptの構文確認、自動テスト36件、文書同期チェック、文書チェックテスト11件がすべて成功しました。Ginoの独立検証では、実ブラウザ＋実Codex接続の一連の操作、Tab移動、通信断と復旧、失敗・中断後の停止案内、案1の設定初期値オフ・キーガード・音声停止後の遅延説明抑止・説明読み上げトグル切替時の遅延応答抑止（画面表示のみ行い音声再生APIへ送らないこと）を確認しています。音声は再生APIの呼び出し記録による確認であり、実際の音質の評価ではありません。

実際の音質、VoiceOver等との併用（キー競合の有無を含む）、非エンジニアや視覚障害のある利用者による理解度は未確認です。実接続の承認要求は、固定の練習タスクでは発生しないため、模擬接続と単体テストによる確認に限ります。詳細は [handoff 2026-10-31](../../handoff/status-2026-10-31.md) を参照してください。

Ginoによるキーボード・表示の検証だけでは、VoiceOverとの併用、日本語の音声品質、非エンジニアや視覚障害のある利用者の理解度を合格としません。利用者の評価では、「今の作業」「確認できた変更」「自分が決めること」を本人の言葉で説明できるか確かめます。
