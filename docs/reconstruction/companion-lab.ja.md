# 共通基盤の体験デモ

このデモは、B案の第一段階です。架空の開発作業を二人の実況と解説で追い、判断する流れを試します。実際のCLI操作、ファイルの修正、修正案の共有、AIへの質問送信は行いません。

## 試す流れ

デモを開始し、段階を進めてください。「いまの作業」「変わったこと」「あなたの判断」と、二人の発言を確認します。音声は必要なときに再生します。

テストが失敗した場面から再修正・再テストへ進みます。共有の承認待ちになったら、詳しい説明を聞く、保留する、承認する、拒否する、の違いを確かめます。承認しても実際の共有は行いません。

「読み上げを止める」と「作業を止める」は別です。作業停止は、この架空シナリオの進行を止めます。

キーボードではTabでボタンを選び、Enterで操作できます。「もう一度読む」で現在の二人の発言を再生します。段階が変わると古い音声と詳しい説明を取り消します。自動で次へ進む機能や常時の音声実況は、今回の試作にはありません。

評価項目は [評価手順](evaluation.ja.md)、全体の方針は [B案の段階移行](README.ja.md) を参照してください。

## 起動方法

開発者向けの手順です。Node.js 24と、このリポジトリのpnpmを使用します。

```sh
pnpm install --frozen-lockfile
pnpm dev:companion-lab
```

起動時に案内されるローカルURLを開きます。現行のCLI Commentatorとは別に起動します。終了するには、起動したターミナルでCtrl+Cを押します。

標準ポートが使用中の場合は、`COMPANION_LAB_PORT=0 pnpm dev:companion-lab` で空いているポートを選べます。接続が切れると画面は状態不明を示します。プロセスを再起動した場合は、ページを再読み込みしてください。前の進行状態は復元しません。

## MCPから操作する場合

MCPクライアントに、リポジトリを作業フォルダとした次のstdio起動コマンドを指定します。

```sh
pnpm --silent mcp:companion-lab
```

`--silent`は、プロトコルの出力に起動案内が混ざらないようにする指定です。接続情報の案内は標準エラー側に出ます。クライアントで表示される案内から、このMCPプロセスが提供する画面を開きます。通常モードで別に起動した画面は、別インスタンスです。

MCPでは架空デモの開始・進行・状態確認・説明・停止を操作できます。承認待ちはAIだけで通過できません。この試作品では、人の承認・拒否は対応する画面から行います。

まず `get_demo_state` で現在の `generation`（状態の更新番号）を取得し、`start_demo` または `advance_demo` の `expectedGeneration` に渡します。古い番号を使った再送は進行しません。画面は約1秒間隔で同じ状態を取得します。

クライアントのツール一覧と入力スキーマに従ってください。このMCPは実CLIを操作する権限を提供しません。

## 自動検証

```sh
pnpm typecheck:companion-lab
pnpm test:companion-lab
```

専用のGitHubワークフローでも確認します。自動検証が通っても、聞きやすさや視覚に頼らない操作の確認が済んだことにはなりません。

## 現時点の限界

- 説明は架空シナリオに対応した固定の台本です。ローカルLLMによる生成は後続段階です。
- 状態はメモリ上だけに保存します。プロセスを終了すると消えます。
- 音声はブラウザの読み上げ機能を暫定使用します。利用できる声や処理場所は環境に依存し、異なる二つの声や完全オフラインの音声処理は保証しません。
- 音声入力、実作業の停止、実作業の承認、他CLIとの連携はまだありません。
- 人の承認経路とMCPツールの分離はデモの入口での制約です。端末全体を自由に操作できる別プログラムに対する本人確認機構ではありません。実作業接続時には権限・本人確認・承認記録を設計します。
